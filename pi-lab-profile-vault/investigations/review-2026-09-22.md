# Full review, 22 Sept 2026

Four reviewers, one lens each (statusbar; fleet + rounds; endpoints/outputs/image-window/code-panels;
tests/CI/scripts/docs). **Every high and medium finding below was independently re-verified against
the code or the installed host source before ranking**; reviewer claims that did not survive that
check are not here. "Unverified" marks the one or two places where the mechanism is proven but the
triggering condition could not be pinned down statically.

Pi moved from 0.86.1 to **0.87.0** during the review window. All three upstream canaries still pass,
so the workarounds in [[../architecture/upstream-workarounds]] are still needed — the canaries doing
their job on their first real version bump. The README and the vault's `verified-against` still say
0.86.1.

## High

### H1 · rounds.ts — `/reload` during a round kills the session ~20 minutes later
`round()` is launched as `void round(ctx, task, rounds, false, seats)` (two sites) with no `.catch`.
`session_shutdown` does only `dead = true`. The phase completion timer (`SPAWN_TIMEOUT_MS`, 20 min) is
cleared only on the three normal-exit paths, never on shutdown; after a reload the completion
listeners are gone (the host unsubscribes every `pi.events.on` of the old activation), so that timer is
the only way out. When it fires, the seat retry runs — gated on `!cancelled`, not `!dead` — and
`runPhase → spawn()` calls `pi.events.on` on the stale activation, which throws. The rejection climbs
out of `Promise.all` and `round()` to the `void`, and Pi has an `uncaughtException` handler but **no
`unhandledRejection` handler**, so on Node 22 it exits. Secondary: in `spawn()` the reply timer is armed
one line *before* `const unsub = pi.events.on(...)`; if that `on` throws, the timer later hits `unsub()`
in its temporal dead zone — a `ReferenceError` from a timer.
**Fix.** Keep pending phase resolvers and timers in a module-level set; on `session_shutdown` clear the
timers and resolve each with `{ status: "error", error: "session reloaded" }`. Have `runPhase` return
that error immediately `if (dead)`, `round()` break on `dead`, `round(...).catch(...)` at both call
sites, and declare `unsub` before arming the timer.

### H2 · statusbar.ts — the `resize` listener is added per activation and never removed
`process.stdout.on("resize", scheduleResizeSettle)` is guarded by a *per-activation* `resizeHooked`;
`session_shutdown` clears `resizeTimer` but never calls `.off`. `scheduleResizeSettle`'s 120 ms
callback has no `dead` check and ends in `tui.renderNow(true)`. So every `/reload` adds a listener:
after N reloads one resize schedules N dead timers that each force a full repaint; each dead closure
pins its whole activation (`ctxRef`, slots, caches, `prof`) for the process lifetime — the one
genuinely unbounded leak in the repo; after 10 reloads Node prints `MaxListenersExceededWarning` over
a fullscreen TUI. It does not throw today only because `tuiRef` is the InteractiveMode-owned proxy
rather than the per-activation ctx. This is exactly the shape of [[../00-start-here|invariant 1]].
**Fix.** `process.stdout.off("resize", scheduleResizeSettle)` in `session_shutdown`; `if (dead)
return;` at the top of `scheduleResizeSettle` and inside its timer.

### H3 · statusbar.ts `guardHover` — the "pi-cc has not patched" refusal is unreachable
The TUI handed to extensions is a proxy whose `get` trap returns a **fresh arrow function for every
function-valued read** (`tui-renderer.js`, `createInteractiveTuiReference`). So
`piccHandler === own.handleViewportInput` can never be true: the refusal branch never runs,
`/compat` always says "active", and the guard captures *whatever it first reads*. If that first read
happens before pi-cc's `setWidget` factory has installed its patch, the guard has captured the bare
prototype path and then overwrites pi-cc's real patch on every frame for the rest of the session —
pi-cc's click handling silently dead, `/compat` reporting success. Both factories run synchronously
at registration, so the race is decided by extension `session_start` order against this file's
`setTimeout(0)` mount; it is real but ordering-dependent (**unverified** which way it falls on any
given machine). The proxy also explains the earlier `775× installed` — it was never churn.
**Fix.** Nothing reachable through the proxy can identify the handler. But when the wrapper runs,
`this` is the **real** TUI (the alt-screen constructor calls `this.handleViewportInput(data)` on the
real object). Capture the real TUI on the wrapper's first call, then read
`Object.getOwnPropertyDescriptor(realTui, "handleViewportInput")` directly: an own property that is
not ours is pi-cc's patch; absence means the prototype. Patch and compare on the real object from then
on. The documented `onTerminalInput` route is **closed**: the alt-screen TUI registers its own viewport
handler as an input listener in its constructor, before any extension can, and it consumes mouse
packets — verified, and confirmed by pi-cc's own comment that mouse never reaches its listener.

### H4 · scripts/check.sh — the boot guard passes vacuously
It greps the log for known failure strings and never checks that the `ok` reply arrived or that Pi
exited cleanly. A stub `pi` that prints `Error: No model configured` and exits 1 gets `boot: clean`; a
Pi killed by the 45 s alarm gets `Alarm clock: 14 … boot: clean`. That second output appeared twice in
the session that built most of this code and was read as a pass each time. Every "boot: clean" in the
commit history is weaker than it looks.
**Fix.** Require the positive signal (`grep -q '^ok' "$log"`) and check the exit status of the `perl
… pi` invocation; fail loudly on the alarm.

### H5 · docs/setup-guide.md — tells strangers to unpack a tarball that does not exist
Part 2 says the files "ship as `pi-lab-kit.tar.gz` alongside this guide" and instructs
`tar xzf pi-lab-kit.tar.gz` then `cp pi-lab-kit/extensions/*.ts ~/.pi/agent/extensions/`. No such
file exists anywhere, the guide is in the npm `files` list and linked from the README, and copying
into `~/.pi/agent/extensions/` produces the double-load that `scripts/install.sh` explicitly warns
about. This is the public install story, and it is wrong.
**Fix.** Replace the Part 2 preamble with the real flow (`pi install git:…` + `scripts/install.sh
lab`); delete every tarball reference; see M14 for §7b.

## Medium

- **M1 · rounds.ts `round()`** — two rounds can run at once: `if (running) return …` is checked,
  then `await subagentsReady()` (up to 1 s), *then* `running` is set. Two commands in that window
  share `live`/`cancelled`/`running`; the second's `live.clear()` orphans the first's agents from
  `/round stop`. Fix: set `running` before the await (clear it on the early return).
- **M2 · rounds.ts `runPhase()` timeout branch** — calls `stop()`, which is the *unsubscriber*, not
  `stopAgent()`. The agent keeps running unreachable by `/round stop`, its eventual completion is
  nudged into the main model (costing a turn), and the retry seat runs alongside it. The local name
  `stop` beside `stopAgent` invites exactly this. Fix: `stopAgent(id)` before resolving; rename the
  unsubscriber; `live.delete(id)` only once the terminal event has arrived.
- **M3 · rounds.ts `count()`** — `new RegExp(\`\\b${word}\\b\`, "gi")`: case-insensitive and
  unanchored, so "nothing was confirmed" and the critic's mandated bottom-line paragraph inflate the
  tally, and `if (!count(carry, "CONFIRMED")) break` can run a needless dev round. Fix: drop `i`,
  anchor to a verdict line; better, require a `TALLY:` line in `critic.md` and parse that.
- **M4 · rounds.ts `carry`** — the next dev round receives the *whole* critique, REJECTED entries
  included, under "findings to address". Fix: pass only CONFIRMED (optionally PLAUSIBLE) entries, or
  say so in the prompt.
- **M5 · fleet.ts `s` (steer)** — `void ctx.ui.input(…).then(async …)` with no `.catch`; with no
  `unhandledRejection` handler in Pi, a rejected `steer()` or a stale `notify` exits the process.
  The `input` hook and `/agent-model` beside it both use try/catch. Fix: `.catch` + `if (dead)`.
- **M6 · statusbar.ts `patchTextWidthCache`** — the probe (`textPatchApplies`) runs *before* the
  `proto[TEXT_PATCH]` check, and `new Text()` renders through the already-patched prototype, so from
  the first `/reload` onward it reports "upstream fixed" and `/compat` says the patch is retired while
  it is in fact active. Fix: check `proto[TEXT_PATCH]` first and report "installed by an earlier
  activation".
- **M7 · statusbar.ts `ContextTrail`** — the window is 60 *samples*, not 60 seconds; samples are
  taken only on cache-miss frames, so after an idle stretch `rate()` and `full in ~N min` average
  across the gap. The class comment and the vault both describe the behaviour the code does not have.
  Fix: age-based eviction (`while (now - samples[0].at > 60_000) shift()`).
- **M8 · statusbar.ts `mountSidebar`** — reachable from two `setTimeout(0)` sites, no `dead` guard;
  a timer straddling shutdown re-mounts the dead activation and overwrites `hook.onRoot`, clobbering
  the new activation's handler. Fix: `if (dead) return;` first.
- **M9 · outputs.ts `openInEditor`** — `$EDITOR`/`$VISUAL` is spawned `{ detached: true, stdio:
  "ignore" }`, so `vim`/`nano` (the common defaults) open nothing while the user is told `→ vim`.
  Fix: detached spawn only for the GUI candidate list; fall back to "Wrote <file>" for terminal
  editors.
- **M10 · outputs.ts `session_shutdown`** — `rmSync(dir)` runs on `/reload` too (reason unchecked),
  deleting files an editor still has open. Fix: `if (event.reason === "reload") return`.
- **M11 · endpoints.ts `probeAlcf`** — `const [cluster, framework] = base.slice(…).split("/")` is
  positional; Minerva/Metis URLs (`…/<cluster>/api/v1`) yield framework `"api"`, so `alcfOffered`
  finds nothing for them and a failed `jobs` call degrades to `? unknown` instead of `? listed`. Only
  Sophia (`/vllm/v1`) ever matched. Fix: union `models` across `clusters[cluster].frameworks`.
- **M12 · endpoints.ts `getJson`** — undici's real reason lives on `error.cause` and is discarded;
  users see bare `fetch failed`; the globus hint regex misses timeouts. Fix: rethrow with
  `cause?.code`, add `TimeoutError|aborted` to the hint.
- **M13 · .github/workflows/ci.yml** — the weekly cron's comment promises to catch Pi releases that
  break the workarounds, but CI never installs Pi, so all three canaries `skip` and the cron verifies
  nothing Pi-specific. Fix: install `@earendil-works/pi-coding-agent@latest` + pi-cc in the cron job,
  or delete the cron and its promise; make skips print their reason.
- **M14 · docs/setup-guide.md §7b / §14 / §15** — §7b embeds a byte-identical copy of
  `code-panels.ts` with nothing keeping it identical and tells the reader to create it under
  `~/.pi/agent/extensions/` (double-load again); §14 describes a Minerva + Sophia panel "pinned" in the
  agent files, but the shipped config puts both seats on Minerva and CI *forbids* pins in agent files.
  Fix: link instead of embed; rewrite §14/§15 from `rounds.json`.
- **M15 · scripts/check-docs.sh `--fix`** — a note with `source:` but no `source-hash:` prints
  "updated" while writing nothing (the `sed` matches no line); with `--fix`, a GONE source still exits
  0. Fix: insert the line when absent; exit non-zero on GONE regardless.
- **M16 · tests/paint-diff, context-trail, hover-guard** — all three slice source between two
  `indexOf` markers without asserting either was found; a moved marker yields a bare `SyntaxError:
  Unexpected token` with no mention of the marker, and in hover-guard an empty slice fails four tests
  with messages asserting a *design violation* that did not happen. Fix: a `slice(src, start, end)`
  helper that asserts both indices; a header line naming the identifiers the structural tests depend on.
- **M17 · agents/critic.md** — its verdict words are machine-parsed (the tally, and whether a second
  dev round runs) and the file does not say so; a rewording silently breaks both. Fix: a short block
  stating the contract, one word per finding, at line start, nowhere else.

## Host facts learned (to fold into [[../architecture/pi-internals]])

- The `tui` given to extensions is `createInteractiveTuiReference(() => renderer)`: a proxy whose
  `get` mints a **new arrow per read of any function**, `set` forwards to the real TUI, non-function
  values (including symbol-keyed objects) pass straight through. Identity checks on methods are
  therefore impossible through it; symbol-keyed hook objects work. Inside a wrapper you installed,
  `this` is the real TUI.
- `TuiAltScreen` registers `handleViewportInput` as an **input listener in its constructor**, ahead
  of every extension listener, and it consumes mouse packets. Extensions cannot see mouse input
  through `onTerminalInput`. `TerminalInputHandler` returns `{ consume?, data? }`; `consume`
  short-circuits the whole pipeline.
- `setExtensionFooter` and `setExtensionWidget` invoke their factories **synchronously at
  registration**.
- On `/reload`: `session_shutdown` → `runner.invalidate()` (unsubscribes every `pi.events.on` of the
  old activation, clears extension terminal-input listeners and widgets) → `session_start`. After
  invalidation, `pi.events.on/emit`, `pi.sendMessage` and every `ctx` getter throw.
- The event bus wraps listeners in try/catch; the only throw `pi.events.emit` can produce is the stale
  assert. A throw inside a slash-command handler is reported, not fatal. Pi installs an
  `uncaughtException` handler that exits and **no `unhandledRejection` handler**.
- pi-subagents: `subagents:failed` covers `error|stopped|aborted`; `awaitStartup` resolves immediately
  for non-worktree spawns; slash commands are dispatched before input handlers, so `/attach main`
  works while attached; a `consume` sent while an agent is still running is refused.

## What is solid

- The once-ever wrapper pattern (symbol-keyed hooks on the TUI, tag-gated patches on the document,
  ScrollView and `Text.prototype`, counters through `sink`) is consistently applied and is the only
  pattern that *can* work through the proxy. No stacking path was found anywhere after the fix.
- The stale-activation discipline on **render** paths is complete: `alive()` before every `ctx`
  touch, root handed back on shutdown, GC observer disconnected, ticker cleared and self-clearing,
  `sessionModelId()` defensive. The gaps (H1, H2, M5, M8) are all on timers and promise continuations.
- rounds' RPC plumbing is correct in the steady state: unique reply channels, both timers and both
  listeners released on every normal path, the no-model retry, stop-on-arrival for a mid-spawn cancel;
  panel semantics match the vault.
- `image-window.ts` is the cleanest file in the repo: pure core, no captured `ctx`, no listeners,
  never mutates input. `code-panels.ts` gets invariant 2 right.
- The memo key honours invariant 3 to the letter; the vault's drift detection works (this review
  flipped two notes stale and back); the hover-guard structural tests protect a real, twice-hit crash.

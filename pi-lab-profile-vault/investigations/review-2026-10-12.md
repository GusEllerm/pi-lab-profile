# Pre-demo house cleaning — upgrade and stability review, 12 Oct 2026

Asked for before a live demo: bring Pi and every package up to date, and deal with whatever
threatens stability. Two strands: a staged upgrade, and an independent review of the extensions
(read-only, told about two known items and nothing else, so its read was not anchored on mine).

## The upgrade

| | before | after |
|---|---|---|
| Pi (`@earendil-works/pi-coding-agent`) | 1.0.1 | **1.1.0** |
| pi-cc-extensions | 0.8.71 | **1.0.2** |
| @tintinweb/pi-subagents | 0.19.0 | **0.21.0** (0.20+ requires Pi ≥ 1.1) |
| pi-agent-browser-native | 0.6.13 | **0.9.5** |
| @juicesharp/rpiv-ask-user-question | 2.12.0 (unpinned) | **2.13.8** (pinned) |

Staged first: Pi 1.1.0 installed into a scratch prefix, a scratch `PI_CODING_AGENT_DIR` mirroring
the real one with the new pins, and the same harness run against both before anything real was
touched. Then `settings.json` backed up (`settings.json.bak-20261012-pre-1.1`) and the real
install done.

- **Canaries:** all three upstream bugs the profile works around are still present in pi-tui 1.1.0
  and pi-cc 1.0.2 (pi-cc's terminal-width hover hit test now appears in two places), so every
  workaround stays and `/compat` reports all three active.
- **pi-subagents surface:** the manager symbol, `getRecord`, the record fields fleet reads, the
  lifecycle events and the cross-extension RPC are unchanged (the RPC file is byte-identical).
  0.20 fixed `@handle` mentions on Pi 1.x — they had been silently falling back on 1.0.1 + 0.19 —
  and dropped `typebox` from `dependencies`, which removes the startup warning.
- **pi-cc 1.0.2 ships its own footer and a sticky-prompt row**, which compete with this profile's
  footer and pin bar. Both are off in `~/.pi/agent/pi-cc-extensions.json`
  (`enableCustomFooter: false`, `stickyUserMessage: false`); its config file was renamed from
  `claude-code-style.json`, whose `previewLines: 0` was carried over.
- **Supply chain**, per the setup guide's rule that pins follow a source review: no install hooks,
  no network calls in any new version. New subprocesses: pi-cc's `git` for the footer's diff stats
  (off with the footer), ask-user-question opening `$EDITOR` on request.
- `lastChangelogVersion` is 1.1.0, so the "what's new" page will not greet a demo audience.

## Findings and fixes

| # | where | what the user would have seen | fix |
|---|---|---|---|
| 1 | hpc-bridge.ts | **16–19 s freeze on every start and `/reload`**: the skill lookup walked uv's whole 37 GB cache synchronously (startup 17.8 s with it, 2.4–4.2 s without) | look only where uvx unpacks wheels (~0.3 s); advertise the installed copy at once, refresh in the background, once per process |
| 2 | statusbar.ts | after any subagent spawned, the hover guard was off: pi-subagents re-runs every factory in-process, and the child's factory took the global sink | claim `sink.prof`/`sink.suppressHover` in `mountSidebar` (UI activations only) |
| 3 | argo.ts | **process exit**: `/new` or `/reload` while `/argo up` was registering made `registerProvider` throw from an uncaught continuation | `dead` after every await, guarded notices, caught chains, abortable Duo dialog |
| 4 | argo.ts | every start, `/new`, `/resume`, `/reload` and subagent spawn waited up to 13 s on a half-open tunnel | 800 ms health, 3 s catalogue, background fallback; pricing once per process |
| 5 | liveness.ts | a running subagent read "queued — not stuck" (`started` precedes `created`) | either event creates the entry; never downgrade; the ticker retries the subscription |
| 6 | liveness.ts | polling (`poll_task`, `ensure_endpoint_up`) reported as **looping**, red until the next turn | same call *and* same result, pollers exempt, cleared by a reply without tools, evidence clipped |
| 7 | hpc-bridge.ts | "Restart a billed compute block?" on every poll while a block provisioned | a fresh `provisioning` result counts as live |
| 8 | hpc-bridge.ts | `grep -n "apiKey:" …` and similar blocked as inline credentials | local bash needs a literal secret-like value; hpc-bridge's own pattern stays on its remote shells |
| 9 | fleet.ts | after ↓ in an empty editor, the next message's first letter could steer a subagent | any other key releases list focus; a departed agent's focus clears |
| 10 | fleet.ts | attached to a finished agent, "Sent to the agent." and nothing | steer only `running` agents; give the text back |
| 11 | fleet.ts | 3.5 ms and 4 MB per frame attached to an agent with a screenshot | `contentSize()` memo key, O(blocks) |
| 12 | paste-guard.ts | fast typing and autorepeat (a held backspace) treated as a paste | 5 ms window, measured: pi-tui emits a chunk's keys in one synchronous loop; autorepeat is ≥ 15 ms |
| 13 | argo.ts | a stale Duo dialog after the 3-minute kill | dismissed through its `signal` |
| 14 | package.json | `pi.skills` pointed at a deleted `./skills` | removed |

## Evidence of stability over time

`~/.pi/agent/crashes.json` holds five crashes, all on 20–21 Sept, each matching a bug fixed that
week (fleet's timer on a stale ctx; the hover-wrapper recursion). None in the three weeks since.

## Verified

94 tests (from 86), 0 skipped, canaries against the real installs. Boot clean. Live on the real
upgraded setup: column, footer, pin bar, `/compat`, a real turn, `/endpoints`, `/stuck`, `/hpc`; a
real Explore subagent through fleet and liveness (`ok · streaming`); hover guard 200/200 after a
spawn; unbracketed paste whole, 20 ms typing and 15 ms backspaces untouched. Frame time with the pty
drained: 6.3 ms, worst 8.6 ms — the ~0.4–1.1 s "slow frames" in some harness runs were the harness
not draining the pty, 80% write time, and vanish when it does.

## Not verified live

The Duo prompt itself (needs a phone), a full `/round` against the ALCF models (cold starts), and
starting a billed hpc block (spends allocation). All are covered by tests and were not changed in
ways those tests miss.
